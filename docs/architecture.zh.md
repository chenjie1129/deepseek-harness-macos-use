# Agent Note: macOS GUI 与浏览器使用

Status: implemented

[English](architecture.md) | 中文

## 问题

Harness 可以编辑文件并运行 shell 命令，但对于仅通过 macOS GUI 或渲染后的浏览器页面提供功能的应用，它没有明确的能力接缝。如果把桌面控制直接加入一个面向模型的工具，就会在同一个包里混合操作系统执行、浏览器生命周期、视觉提供方配置、循环策略与结果持久性。

## 决策

实现新增由四个包组成的 `macos-use` 家族。专用 GUI 模型服务把截图发送到可配置的 OpenAI 兼容视觉端点，因此 GUI 定位不要求驱动模型接受图片输入。端点、模型、输出上限和凭据引用都是可实时更新的可视化插件设置。P0 在像素观察之外加入语义窗口观察路径：应用与窗口发现、精确窗口截图、扁平化辅助功能元素，以及在新快照或窗口几何变化后过期的不透明元素令牌。推荐的部署补丁只挂载服务；所有可调智能体配置仍位于插件配置页面。

## 能力拆分

- `@deepseek-ai/dsh-macos-use` 负责通过 `ctx.subprocess` 执行“只包含已授权前台窗口”的全黑主显示器坐标画布、精确窗口截图、应用／窗口发现、辅助功能状态、目标受约束的 System Events 操作、CoreGraphics 指针移动／拖动和精确应用启动。调用方自定义的任意 AppleScript 始终被拒绝。
- `@deepseek-ai/dsh-browser-use` 负责一个延迟启动的 Playwright Chromium 进程，为每个 Harness Agent 提供独立的上下文、页面、Cookie 与观察状态，并通过带认证的环回代理对每条出站连接进行校验、解析和 IP 固定。它提供选择器、文本、键盘、坐标、拖动和截图操作；实时变更浏览器策略会在下一次动作前停用全部上下文与代理。
- `@deepseek-ai/dsh-gui-model` 负责一次独立的截图到动作请求，并校验返回的动作联合类型。
- `@deepseek-ai/dsh-tool-macos-use` 负责面向模型的基础 schema，以及有边界的桌面和浏览器动作循环。

## 实验性 Ego Lite 后端

除默认的 Playwright 安全后端外，`@deepseek-ai/dsh-browser-use` 还可通过 [ego lite](https://github.com/citrolabs/ego-lite) 的 `ego-browser` CLI 驱动该浏览器。这是一项**实验性**集成，由 `browserBackend` 设置选择（默认值：`playwright`）。

**风险警告——启用前必读：**

- **不具备固定代理的网络隔离。** Playwright 后端把每次导航、重定向、子资源请求和 WebSocket 都强制送入带认证的环回代理，由代理校验主机名、对出站连接做 DNS 固定，并拒绝私有网络目标。Ego 后端直接驱动 ego lite 浏览器，**不**提供等效的网络隔离。导航前仍会校验域名授权与拒绝规则，但子资源请求、DNS 行为与连接固定均由 ego lite 自身治理，而非本插件的代理。
- **需要 ego lite 应用。** 必须已安装 `ego-browser` CLI 且位于 PATH 中。插件从不下载、安装或导入浏览器配置。CLI 缺失时会以 `BROWSER_USE_LAUNCH_FAILED` 报错并给出安装指引。
- **操作集有限。** 首个 Ego 后端版本只映射 `navigate`、`clickSelector`、`fillSelector`、`extractText`、`screenshot`、`pageState` 和 `releaseOwner`。基于坐标的动作（`clickAt`、`moveAt`、`dragAt`、`scroll`、`type`、`key`）以及由视觉模型驱动的 `browser_use_task` 循环**不受支持**，会以 `BROWSER_USE_UNSUPPORTED_ACTION` 失败。
- **并发被强制为 1。** 所有 Ego 操作通过单一互斥锁串行执行。多个智能体无法并发运行 Ego 浏览器操作。
- **模型不提供 JavaScript。** Host 为 `ego-browser` CLI 生成固定的操作脚本。模型绝不提供原始 JavaScript、`evaluate` 表达式或 CDP 命令。
- **owner 隔离。** 每个 Harness Agent 拥有自己的 ego lite Task Space。Task Space 会在 `releaseOwner`、Agent 销毁和服务拆除时释放。

## 安全与持久性

macOS“辅助功能”和“屏幕录制”权限仍由宿主控制。浏览器网络和 macOS 应用访问默认拒绝；精确的读取／控制授权、全局应用拒绝规则、浏览器域名授权与私有网络访问都在可视化页面配置。控制授权必须有相同或更宽泛的读取授权，避免原生动作已经生效，却因动作后证据不可读而被报告成失败。拒绝规则优先于授权。显示器坐标路径绝不会生成完整显示器 raster：它只截取经过精确授权的前台窗口，再把它放到一张合成的全黑画布上；被排除、不可读、不在主屏、跨屏、部分超出或截图期间变化的目标均失败关闭。针对被排除内容的精确窗口截图也会直接失败。调用方自定义的任意 AppleScript 始终不可用。每个直接或模型选择的 GUI 变更动作前的一次性确认默认开启。只有当部署具备等效、可信的安全或审批边界时，操作者才应关闭它；关闭后仍可按配置对破坏性拖动、按键和任务意图进行启发式确认，但这不是语义效果保证。

桌面坐标、窗口和辅助功能观察会签发绑定 owner 的一次性令牌。服务会在任何异步复查前占用令牌，并在分派前立即校验进程、bundle、窗口身份、边界、显示器几何、mutation epoch，以及语义路径中的元素身份。所有原生变更从复查到分派共用一个服务级队列；分派会推进 epoch，并撤销所有其他待用的桌面观察。浏览器截图观察绑定 owner／页面／URL／过期时间，并携带必须在坐标或键盘动作分派前与新鲜截图一致的视口摘要。导航、重定向、子资源与 WebSocket 被强制送入带认证的环回代理；代理会重新校验主机名，为该出站连接执行一次 DNS 解析，除非启用私有网络，只要答案集含任一非公网地址就整体拒绝；然后把 socket 固定到数字 IP，同时保留 Host 与 TLS SNI。Chromium DNS 退路、隐式环回绕过、QUIC、Worker、WebRTC 和 WebTransport 都会被禁用。这是纵深防御，不是操作系统网络沙箱。单任务锁、任务总超时、命令超时、仅当前 owner 可用的模型中止，以及全局可视化紧急停止共同约束自主控制；这组包不会创建持久的操作系统权限授权。

动作循环采用“无法确定即停止”：格式错误、超限、不支持、过期或无法验证的动作不会退化为最佳猜测。模型声明 `done` 是必要条件，但不足以代表成功。Host 会从选定浏览器或 macOS 目标捕获一份新鲜、原子的完成快照，在这份快照上验证请求的后置条件，然后才设置 `completed: true`。

截图字节通过 `ctx.attachments` 保存，而驱动模型只接收文本引用，因为其主要适配器拒绝图片工具结果内容。GUI 模型请求与中间决策位于驱动 Session 日志之外。默认开启的展示设置会把每个可用步骤截图保存为有界、经过授权的仅 UI 结果内容。它覆盖已完成任务和插件能够捕获并结构化返回的停止／错误结果；调用方强制取消时不会产生工具结果，只能保留短时、尽力而为的进度。面向用户的进度与持久任务历史会把 `type` 动作载荷替换成字符数占位符；这不会遮盖截图像素里本来可见的文字。最终任务结果仍会保留完成状态、摘要、已脱敏的动作与结果列表、验证状态以及最终截图引用。存储副本会按当前附件限制进行规范化，但不会改变用于定位的原始像素或动作坐标。

工具包同时具有 Host 与 Client 两个 face。Host 通过 Typert 服务生命周期挂载进度桥，把实时快照绑定到可信 Agent 与工具调用身份，并把保留的步骤图片投影到 `tool/result.data.meta.content`；Session Controller 授权这些引用，Session 导出会包含其对象。Client 校验该元数据，通过 Session 附件线路加载图片，并在 keyed `tool.call.toolview` slot 中渲染任务卡。截图被规范化缩小时，任务输出 schema 会接受附件服务提供的可选 `originalDimensions` 元数据。

## 考虑过的替代方案

- **仅使用 shell 控制。** Shell 命令无法可靠观察或操作那些有意义状态只存在于渲染界面的应用。
- **单体插件。** 单个包会耦合浏览器、桌面、提供方、设置、工具 schema 与循环变更，无法独立替换或进行聚焦测试。
- **使用驱动模型视觉能力。** 要求主智能体模型消费截图，会使桌面能力依赖该模型的模态支持，并把大型图片结果放进普通对话历史。

## 验证

插件 Vitest 门禁在 23 个文件中通过 346 项测试，Host 与 Client TypeScript 项目以及完整集成 Harness 构建也在已经证明的 Harness `0.1.2-alpha.1` 基线上通过。测试覆盖目标受约束的原生脚本构造、macOS 服务行为、观察 owner／并发／过期、Retina 几何、只包含前台窗口的截图、任务协调与中止、GUI 响应解析与有界请求、浏览器隔离／网络代理／策略／操作、Ego 后端生命周期／并发／CLI 缺失诊断、策略确认、原子后置条件验证、键入文本输出脱敏、输出 schema 校验、可视化设置卡注册、进度生命周期、授权附件加载，以及有边界的任务循环执行。另外，提示词评测器在 8 个文件中通过 19 项测试，并通过了使用独立 HTTP 判定器的确定性“提示词到浏览器”冒烟测试。

发布证据会分别记录逻辑、类型、构建、打包、兼容性、确定性提示词、真实提供方与渲染 UI 门禁。渲染 UI 门禁会打包实际的 `SettingsCards` 与 `GuiTaskView` 组件，验证默认开启、开启时 1 张图片、关闭时 0 张图片、无控制台／请求问题及无水平溢出。确定性 fixture 不代表真实第三方提供方兼容性，当前证据也不宣称完成了解锁原生 macOS 应用后的截图／动作 E2E，或 `0.1.2-alpha.5` 精确源码的编译／构建／启动兼容性。

## 结果

产品可以独立组合桌面执行、浏览器执行、GUI 定位和面向模型的工具，同时让驱动模型保持仅文本。所有可调整的 P0 智能体选项都可在插件配置页面的 GUI 模型或 GUI 智能体卡中可视化设置。因此，推荐的 [`macos-use.cordis.patch.yml`](../integration/macos-use.cordis.patch.yml) 只包含四项服务挂载，可调键为零。这样的拆分增加了明确的安装要求：必须存在 Playwright Chromium，宿主必须拥有操作系统权限。中间 GUI 步骤可在实时进度和最终结果中观察，也可以选择同时显示其截图，但不是独立持久的 Session 事件。
