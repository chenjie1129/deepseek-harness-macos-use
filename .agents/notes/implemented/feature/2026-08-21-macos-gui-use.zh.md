# Agent Note: macOS GUI 与浏览器使用

Status: implemented

[English](2026-08-21-macos-gui-use.md) | 中文

## 问题

Harness 可以编辑文件并运行 shell 命令，但对于仅通过 macOS GUI 或渲染后的浏览器页面提供功能的应用，它没有明确的能力接缝。如果把桌面控制直接加入一个面向模型的工具，就会在同一个包里混合操作系统执行、浏览器生命周期、视觉提供方配置、循环策略与结果持久性。

## 决策

实现新增由四个包组成的 `macos-use` 家族。专用 GUI 模型服务把截图发送到可配置的 OpenAI 兼容视觉端点，因此 GUI 定位不要求驱动模型接受图片输入。端点、模型、输出上限和凭据引用都是可实时更新的插件设置。

## 能力拆分

- `@deepseek-ai/dsh-macos-use` 负责通过 `ctx.subprocess` 执行 macOS 截图、System Events 操作、应用启动和 AppleScript。
- `@deepseek-ai/dsh-browser-use` 负责一个延迟启动的 Playwright Chromium 页面，并提供选择器、文本、键盘、坐标和截图操作。
- `@deepseek-ai/dsh-gui-model` 负责一次独立的截图到动作请求，并校验返回的动作联合类型。
- `@deepseek-ai/dsh-tool-macos-use` 负责面向模型的基础 schema，以及有边界的桌面和浏览器动作循环。

## 安全与持久性

macOS“辅助功能”和“屏幕录制”权限仍由宿主控制。任意 AppleScript 和 GUI 操作通过常规工具执行与部署策略界面运行；这组包不会创建持久权限授权。截图字节通过 `ctx.attachments` 保存，而驱动模型只接收文本引用，因为其主要适配器拒绝图片工具结果内容。GUI 模型请求与中间决策位于驱动 Session 日志之外；最终任务结果会保留完成状态、摘要、动作与结果列表以及最终截图引用。

## 考虑过的替代方案

- **仅使用 shell 控制。** Shell 命令无法可靠观察或操作那些有意义状态只存在于渲染界面的应用。
- **单体插件。** 单个包会耦合浏览器、桌面、提供方、设置、工具 schema 与循环变更，无法独立替换或进行聚焦测试。
- **使用驱动模型视觉能力。** 要求主智能体模型消费截图，会使桌面能力依赖该模型的模态支持，并把大型图片结果放进普通对话历史。

## 验证

聚焦测试覆盖 AppleScript 构造、macOS 服务行为、GUI 响应解析与请求、浏览器生命周期与操作、设置卡片注册，以及有边界的任务循环执行。这些包通过仓库构建、hygiene、生成目录、双语文档和推送前类型检查门禁。实时提供方凭据、macOS 权限授予与真实 GUI 端到端套件仍属于部署检查。

## 结果

产品可以独立组合桌面执行、浏览器执行、GUI 定位和面向模型的工具，同时让驱动模型保持仅文本。这样的拆分增加了明确的配置与安装要求：必须存在 Playwright Chromium，宿主必须拥有操作系统权限，并且必须配置兼容的视觉端点。中间 GUI 步骤可在最终结果中观察，但不是独立持久的 Session 事件。
